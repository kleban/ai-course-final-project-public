# Data Story — локальний аналітичний MVP

Data Story допомагає пройти шлях від CSV-набору до аналізу, лінійної регресії, висновків і HTML-звіту. Сервіс створено як фінальний проєкт курсу «AI-агенти для розробників»; він показує принципи аналізу даних, візуалізації та основ моделювання й допомагає студентам вчитися аналітиці.

Опис ідеї та архітектури — сторінка проєкту на GitHub Pages (`docs/`).

## Можливості

- Проєкти, CSV до 5 МБ, таблиця даних, метадані та незалежні копії наборів.
- Описова статистика, пропуски, кореляції; гістограма, розсіювання, теплова карта, графік пропусків.
- Підготовка даних: заповнення пропусків, кодування категорій, поділ на вибірки (типово 70/30); перетворення навчаються лише на навчальній частині.
- Лінійна регресія: коефіцієнти, p-value, R²/MAE/RMSE на тесті, порівняння з простим прогнозом, ручний або покроковий вибір ознак (adjusted R², AIC, BIC).
- Агрегація та з'єднання в DuckDB без написання SQL користувачем.
- База знань (RAG): редаговані правила й уривки книжок; локальні embeddings BAAI/bge-m3 + TF-IDF.
- AI-помічник (OpenAI): поради, виконання дій, пояснення результатів, чернетки описів і графіків; журнал запитів, токени й вартість.
- Висновки з явним затвердженням і звіти через локальний Quarto → HTML.

## Вимоги

- Windows, Python 3.13 із Windows Python Launcher (`py -3.13`).
- Інтернет для першого встановлення (пакети, Quarto, модель bge-m3 ≈ 2,3 ГБ) і для функцій OpenAI. Решта працює офлайн.

## Встановлення й запуск

1. `Setup.cmd` — один раз і після зміни залежностей: створює `.venv`, ставить пакети з `requirements.lock`, портативний Quarto і bge-m3 у `runtime/dependencies/`.
2. `Start.cmd` — запускає сервер і відкриває http://127.0.0.1:8765. Вікно запуску залишайте відкритим.
3. `Stop.cmd` — зупинка.

OpenAI: скопіюйте `.env.example` у `.env` і задайте `OPENAI_API_KEY`. Моделі для задач обирають у «Налаштування → Моделі AI». Без ключа працюють усі локальні розрахунки.

Дані користувача зберігаються в `runtime/` (SQLite, DuckDB, файли проєктів, звіти). `.venv/`, `runtime/`, `tmp/`, `.env` і `sources/` не потрапляють у Git.

## База знань і embeddings

- Правила лежать у `src/data_story/knowledge/` і редагуються в застосунку.
- Книжкові уривки будуються з ваших PDF (у Git не входять):
  1. покладіть PDF у `sources/` (перелік розділів — `src/data_story/knowledge_sources/selection.json`);
  2. `python tools/build_sources.py` — PDF → уривки в `runtime/knowledge-sources/` (потрібен `pdftotext` з poppler);
  3. `tools\windows\Index-Books.cmd` — обчислення векторів bge-m3, оцінка пошуку й повна перевірка.
- `tools\windows\Check-Embeddings.cmd` перевіряє, що модель завантажується так само, як у сервісі.
- `tools/knowledge_eval.py` порівнює TF-IDF і гібридний пошук на контрольних питаннях.

## Перевірки

- `Check.cmd` — `pip check`, ruff, mypy і всі офлайн-тести (`tests/`).
- `Check-Projects.cmd` — лише тести. Автотести не завантажують ONNX-модель і не звертаються до OpenAI.
- `tools/ui/*_ui_smoke.py` — браузерні сценарії (потрібен Playwright, не входить у `requirements.lock`); запускаються проти окремого сервера з порожньою базою, напр. `python tools/start.py --no-browser --port 8899 --database tmp/smoke/data.sqlite3`. Знімки — у `tmp/ui-smoke/`.
- `tools/assistant_live_check.py` — жива перевірка помічника з OpenAI (витрачає токени).

## Демонстраційні дані

- `samples/melb_data.csv` — Melbourne Housing Snapshot (CC BY-NC-SA 4.0), `tools/make_demo_project.py` створює з нього проєкт.
- `samples/seoul_bike.csv` — Seoul Bike Sharing Demand, UCI (CC BY 4.0); `tools\windows\Build-Demo.cmd` і `Build-Demo-Report.cmd` наповнюють робочу базу демо-проєктом (сервер має бути зупинений).
- `samples/demo_apartments.csv` — синтетичний набір для тестів (`tools/make_demo_data.py`).

Деталі й ліцензії — `samples/README.md`.

## Структура

```
src/data_story/   код застосунку (NiceGUI + FastAPI), ресурси, база знань
tests/            офлайн-тести; tests/fixtures/ — незалежні еталонні значення
tools/            запуск, встановлення, перевірки, RAG, демо; tools/ui/ — браузерні сценарії;
                  tools/windows/ — .cmd-обгортки з логами в tmp/
samples/          демонстраційні набори
docs/             сторінка проєкту для GitHub Pages
```

## Обмеження

- Один користувач, один процес, без входу; сервер слухає лише 127.0.0.1.
- Лише лінійна регресія з випадковим поділом; класифікації, кластеризації, PDF/DOCX-звітів немає.
- CSV до 5 МБ; SQL від LLM — до 10 000 рядків.
- Вартість AI — оцінка за фактичними токенами й тарифами з налаштувань, не рахунок OpenAI.
- AI-тексти — чернетки: до звіту потрапляє лише затверджене користувачем.
